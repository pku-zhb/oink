# Oink 物理屏幕分配产品需求

版本：1.0

日期：2026 年 11 月 6 日

目标：在现有实验分支上形成可提交上游 PR 的功能，完成从首次校准到日常切换的用户体验。

用户桌面上有固定数量的物理显示器，每块显示器可以通过不同视频输入口连接多台电脑。Oink 应帮助用户一次性确认物理位置和连接关系，之后直接选择每块屏幕显示哪台电脑，并让键鼠路由、系统桌面和主屏状态与实际可见画面一致。

首版重点支持两块横向摆放的外接显示器和两台电脑。以 Mac 为电脑 1、Windows 为电脑 2，完整支持 11、12、21、22 四种画面归属。系统停用显示器须按实际能力启用；无法完成的能力必须在设置阶段说明，并提供明确的兼容模式，不能静默声称完成了完整桌面切换。

## 一 产品问题和成功标准

### 用户遇到的问题

同一块物理屏幕接入两台电脑后，会在两边分别形成系统显示器身份。显示器切到另一台电脑的输入口时，原电脑可能仍保留该屏幕的扩展桌面，产生以下问题：

- 鼠标进入看不见的桌面，或按系统排列移动到错误的物理方向。
- 应用窗口、对话框和桌面图标出现在当前看不见的屏幕。
- 主屏、菜单栏、任务栏或操作窗口留在看不见的屏幕。
- 用户需要分别操作显示器菜单、系统设置和 Oink，且容易把两边的屏幕身份配错。
- 切换失败后，恢复按钮本身可能不可见。

### 成功标准

用户无需理解 DDC 数值、显示器 UUID 或 Windows 设备路径，即可完成常规配置。校准后，用户在任一具备可见操作界面的配对电脑上选择布局，Oink 协调屏幕输入、系统显示状态和键鼠路由，并提供可达的确认与恢复方式。

完整模式下，12 和 21 布局中的每台电脑只保留分配给自己的外接桌面空间；有可见屏幕的电脑不得将主屏留在不可见屏幕。11 和 22 布局必须可切换画面，并明确处理另一台电脑没有可见外接屏的情况。

验收以真实画面、系统显示状态、实际窗口行为和故障恢复为准。编译通过、DDC 命令返回成功或鼠标路由测试通过，分别只证明相应环节。

## 二 首版范围

### 必须交付

| 项目 | 首版要求 |
| --- | --- |
| 硬件和系统 | 两台受当前 Oink 支持的电脑，重点验证 Apple Silicon Mac 与 Windows；两块横排外接屏 |
| 物理屏幕 | 用户确认名称及从左到右的位置，绑定各电脑上的系统显示器身份 |
| 输入关系 | 引导确认每块屏幕的视频输入口对应哪台电脑，保存校准结果 |
| 校准保护 | 一次只测试一块屏幕，自动恢复，恢复后确认映射 |
| 日常布局 | 11、12、21、22 四种组合，明确显示左右屏归属 |
| 系统桌面 | 对支持且验证通过的平台停用不可见外接屏，并处理可见主屏 |
| 兼容模式 | 无法停用系统显示器时，保留输入切换与路由能力，明确剩余桌面空间问题 |
| 故障恢复 | 超时、取消、界面退出、进程异常、设备掉线后的可恢复行为 |
| 原版兼容 | 未启用此功能时维持原有 Oink 行为；普通配对与现有功能继续可用 |

### 暂不纳入

首版不制作任意二维屏幕排列编辑器，不新增远程桌面视频流，不控制实体 KVM 的 USB 切换，不新增复杂窗口排版器，不承诺所有应用的窗口及桌面图标在往返切换后逐像素恢复，也不同时实现多套 macOS 原生停屏方案。

数据结构应容纳每块屏幕连接不同数量的电脑。界面可将首版验证范围限定为两屏两电脑；超过验证范围时应说明限制。不得因组合数超过内部上限而显示空白列表。

## 三 核心概念

| 概念 | 含义 |
| --- | --- |
| 物理屏幕 | 桌上真实的一块显示器，有独立身份、名称和物理位置 |
| 视频输入口 | 显示器上的 HDMI、DisplayPort、USB-C 等输入；用户可重命名 |
| 系统显示器身份 | 某台电脑为连接到它的显示器分配的身份；同一物理屏在不同电脑上身份不同 |
| 绑定 | 物理屏幕、配对电脑、系统显示器身份和输入口之间经用户确认的关系 |
| 布局 | 每块物理屏当前分配给哪台电脑，以及相应的系统桌面和主屏策略 |
| 完整模式 | 同步切换输入、系统显示器启停、可见主屏和 Oink 路由 |
| 兼容模式 | 切换输入及 Oink 路由，保留无法停用的系统桌面，并向用户说明 |

DDC/CI 是用于控制显示器的接口。当前代码通过输入源控制项切换视频输入。数值及厂商差异由适配层处理，常规界面展示端口名称和电脑名称；原始数值放在高级设置。

显示器可提供型号、序列号、输入口或能力信息，但这些信息不必然能证明线另一端是哪台配对电脑。自动匹配用于提出候选，首次映射仍需用户确认。相同型号且缺少唯一序列号的显示器不得按名称自动合并。

## 四 首次设置流程

### 进入方式和视觉风格

在现有布局设置中提供“设置共用显示器”入口，启动独立分步向导。沿用原版 onboarding 的组件、字体、动效、间距、颜色和交互语言，避免引入另一套视觉风格。不向所有新用户强制展示此流程。

向导展示当前步骤、返回、取消和必要的操作进度。支持键盘操作、读屏和减少动态效果设置。取消须恢复已临时改变的状态，不留下半完成配置。

### 步骤一 检查电脑和能力

列出参与配置的电脑，确认双方在线、已配对、功能协议兼容。检查本地控制权限、显示器可用性、DDC 写入和读回能力，以及系统显示器启停能力。Mac 检查 BetterDisplay 是否存在、接口是否可用及所需功能是否获许可；不得仅凭操作系统类型显示“支持”。

按实际结果展示支持完整模式、支持兼容模式或暂不能配置，并给出具体原因。检查尽量只读；必要的硬件切换进入后续显式测试步骤。无关的其他已配对电脑离线，不应阻止本次两台参与电脑的配置。

### 步骤二 确认物理屏幕和位置

在可见屏幕上显示大号编号和电脑名称，让用户确认“这是左屏”或“这是右屏”。系统排列只作为初始提示，不作为真实物理位置的依据。支持为屏幕命名和交换左右位置。

两边的系统屏幕身份归入同一物理屏幕后，向导展示关系摘要。对无法自动匹配的屏幕，使用逐块识别；不得要求用户区分原始 UUID。初次配置可引导用户临时让双方识别全部目标屏幕，测试结束后恢复。

### 步骤三 校准视频输入口

逐块显示器进行，正常流程如下：

1. 记录可恢复的起始状态，确认至少存在一种可操作的恢复路径。
2. 优先读取当前输入及显示器提供的端口能力。缺少信息时，允许用户通过显示器菜单切换后确认，不在后台盲扫任意输入值。
3. 选择一个候选输入，短暂切换，并在目标电脑对应屏幕上展示明确的识别画面，例如“右屏，当前是 Windows”。
4. 显示“正在测试，将在 10 秒后恢复”，从测试写入成功时起计时；测试本身总是恢复原状态，不以用户能点到按钮为前提。
5. 恢复后询问刚才是否出现预期电脑画面。确认后才保存该映射；失败则重试、换候选端口或进入兼容处理。

“10 秒”是首版目标测试窗口，底层命令必须另有有限超时。界面须如实反映实际恢复进度，不宣称所有硬件在同一精确时刻完成。

支持输入写入但无法读回的显示器，走目视校准：用户先确认当前显示的电脑，再进行有恢复目标的测试。界面说明“已由你确认，显示器不能报告当前输入”；命令成功不能升级为硬件读回确认。

如果原状态未知或没有可信的恢复输入，先让用户确认基线，再发出测试命令。任何可能导致不可恢复黑屏的试探都不应进入默认流程。

### 步骤四 验证系统显示器管理

分别测试参与电脑停用、重新启用目标屏幕的能力，检查重新识别后的身份及恢复结果。12 和 21 中有可见屏幕的电脑，应验证不可见外接屏被系统停用，并确认主屏仍可见。

输入切走后 DDC 是否仍可用，以及系统停用后能否重新启用并重新取得控制，均需验证。某一路径不可用时，应记录可用的控制电脑或回退路径；没有可靠路径则不启用对应的完整模式。

测试 11 和 22 前，说明另一台电脑将没有可见外接屏。若系统或适配器禁止停用最后一块物理屏，保留该电脑的系统显示连接，明确标为兼容处理，不绕过默认保护来换取表面成功。

### 步骤五 确认并完成

展示物理位置、电脑和输入关系，以及各布局的支持程度。一次完成后同步给参与电脑，电脑重启或打开另一端设置不应要求重复配置。需要时可单独重新校准某块屏幕，不必全部重来。

## 五 日常布局操作

### 布局选择

默认提供四张布局卡片。卡片绘制左右两块屏幕，并在每块屏上显示实际电脑名称。11 等数字只用于本 PRD 的说明，不作为最终用户必须学习的术语。

| 组合 | 左屏 | 右屏 |
| --- | --- | --- |
| 11 | 电脑 1 | 电脑 1 |
| 12 | 电脑 1 | 电脑 2 |
| 21 | 电脑 2 | 电脑 1 |
| 22 | 电脑 2 | 电脑 2 |

展示当前布局和切换进度。可见画面无法读回时，状态使用“按已校准关系切换”等准确措辞。遇到外部手动切源、重接线或状态冲突时，应显示需要重新确认，不能把上次命令永久当成当前事实。

未来增加屏幕时，使用“逐屏选择电脑并保存布局”的交互，不依赖穷举所有组合。可复用原有布局配置能力；不要为同一用户意图另建互相冲突的预设系统。

### 应用和确认

点击布局后，一次切换只允许一个协调操作。不同电脑同时发起时，后发者收到明确的进行中提示，不允许双方同时操作同一物理屏幕。

首版每次应用涉及系统显示拓扑变化的布局，默认提供 15 秒“保留布局”和“恢复原布局”。确认入口须出现在切换后可见的参与电脑上；可以从任一可见参与端确认，不能只在原发起端等待确认。没有确认即恢复。

没有改变状态的重复点击不发起新的切换。执行过程中禁止重复应用及修改绑定，保留取消、状态查询和恢复入口。后续是否减少已验证布局的确认步骤，可在硬件和恢复数据充分后再评估。

### 主屏和窗口

有可见系统屏幕的电脑，原主屏仍可见时保留原主屏；否则将分配给该电脑的可见屏幕设为临时主屏。返回之前布局或退出功能时，恢复事先保存的主屏和显示器配置，若硬件变化则执行可行的安全恢复并说明结果。

系统停用不可见桌面后，验证普通窗口、模态对话框、全屏应用、菜单栏或任务栏和桌面图标的可达性。优先使用系统桌面管理行为；必要的窗口救援能力应限定范围，避免为此引入完整窗口管理器或不必要的额外权限。

对应用自记坐标、macOS Spaces 或全屏状态等特殊情况，提供真实限制和可操作的恢复方法，不承诺所有应用精确恢复原窗口位置。

### 退出和恢复

“恢复切换前配置”应同时处理显示器输入、系统启停、主屏和 Oink 路由。恢复参考点为进入本次物理屏幕模式前记录的完整状态；各次待确认操作还须保留其直接前一状态，分别用于退出和取消。

若仍提供仅清除 Oink 路由的操作，使用能说明实际效果的名称，并置于高级设置。不能继续用含糊的“返回普通布局”暗示显示器输入和系统状态也已恢复。

## 六 系统显示器管理和兼容模式

### 完整模式

完整模式要求显示器输入归属、系统桌面、主屏及 Oink 的可见屏幕路由共同生效。各电脑只停用本功能管理且当前未分配给自己的显示器。用户的其他外接屏、笔记本内屏及未纳入配置的虚拟屏保持原有状态。

对于 12 和 21，每台电脑仍有可见目标屏幕，应优先完成不可见外接屏的系统停用。对于 11 和 22，另一台电脑可能保留自己的未管理内屏；没有其他可见屏幕时则进入无可见屏的单独验证路径。

没有可见屏的电脑仍应保持必要的 Oink 通信和输入服务，允许从可见电脑恢复布局。不得要求用户在无可见屏的电脑上点击确认、完成权限弹窗或重新启动服务。

### 平台实现方向

| 平台 | 首版方向 | 必须验证 |
| --- | --- | --- |
| Windows | 使用官方显示配置接口管理启停和桌面拓扑，并在有控制台桌面权限的正确用户会话中执行 | 逐屏启停、主屏、身份重建、无屏行为及恢复；不能只在远程会话或服务状态中推定成功 |
| macOS | 提供可选 BetterDisplay 适配，复用现有输入源控制基础并增加逻辑连接管理 | 可用性和许可、停用与重新启用、控制通道、最后一屏保护及应用退出后的行为 |
| macOS 原生适配 | 为后续适配保留接口，首版不强制实现 | 若另行实现，须明确公开或私有 API、系统支持范围、分发约束和恢复验证结果 |

BetterDisplay 的逻辑断开不同于调黑屏幕或发送显示器电源关闭命令。只有从系统桌面中移除不可见显示空间，才满足本需求的系统停用定义。

### 兼容模式

能力不足可以按电脑或布局降级。应用前显示具体影响，例如“Windows 已停用不可见屏幕；Mac 仍保留扩展桌面，窗口可能出现在看不见的屏幕”。用户确认后才能采用该模式。

兼容模式仍须完成已校准输入切换、可见屏幕的 Oink 路由和失败恢复。不能把兼容模式标为完整模式通过，也不能因为允许降级而跳过对 12 和 21 系统停用路径的实现与验证。

若不能可靠切源或不能恢复，禁用对应布局并说明原因。只是在 Oink 中隐藏逻辑屏幕，不等于系统停用成功。

## 七 切换事务和恢复要求

### 状态管理

后端应提供可查询的操作阶段：检查、准备、切换、等待系统稳定、等待确认、完成、恢复、恢复需处理。界面不靠长请求悬而未决来猜进度；状态查询和取消不应被测试等待阻塞。

切换开始前保存实际可获得的输入状态、显示器启停、几何与显示模式、主屏、Oink 布局和配置版本。无法读回的状态以最近确认的校准基线记录，同时保留其可信程度。

操作必须在参与电脑间协调，并防止过期确认、重复命令、配置版本冲突和双端并发。仅有单进程互斥不能代替跨电脑协调。

### 执行约束

具体启停顺序由平台和硬件验证决定，但必须满足：

- 先建立可恢复状态和超时保护，再进行会影响画面的操作。
- 在停用旧路径前，确认新目标已具备可用路径；需要重新启用的屏幕先进入可识别状态。
- 分别验证输入切换、系统显示配置、可见主屏和路由结果；不能用其中一项代替其余项。
- 重新枚举显示器后，按已确认关系解析身份，不把系统暂时移除的屏幕从永久绑定中删除。
- 部分完成时明确记录中间状态，继续保留恢复能力。旧布局在输入已变化后不能被静默当成当前成功状态。
- 不对失败命令无界重试；每一步有超时，总操作有期限，恢复优先于继续尝试新布局。

DDC 读回一致只能证明显示器报告了相应输入，首次校准仍以用户画面确认建立映射。无法读回的显示器允许按已确认映射执行，但状态与恢复结果不得冒充硬件确认。

### 恢复保护

恢复计时不能只放在前端。关闭设置页、网页或应用窗口不能取消恢复。后台主进程退出时，应有独立恢复机制；整机重启后应能够从未完成的恢复记录中恢复或呈现可操作的处理入口。

恢复记录位于本机应用数据目录，操作结束后清理或收敛为必要配置，不把执行日志、临时快照和恢复记录写入用户的同步阅读目录。

恢复失败时分别说明哪些屏幕输入已恢复、哪些系统显示连接已恢复、当前哪台电脑仍有可见画面，以及下一步如何重新接入。提供可见端的一键重试和脱离当前布局的紧急恢复方式。不得只显示笼统的“切换失败”。

## 八 配置和兼容性

物理屏幕拥有稳定的应用内身份，与某台电脑当前的显示器编号分离。共同配置保存名称、物理顺序和各电脑绑定；本地系统路径、控制权限和适配器状态仍由所属电脑管理。配置需要版本和并发冲突检查。

已保存配置在应用重启后保留，但不能因此推定显示器实际输入从未改变。对重接线、身份变化、睡眠唤醒、设备加入退出及外部手动切源，重新验证可验证的信息；无法确认时保留配置并请求局部重新确认，不偷偷重新配对。

遇到旧版或不支持该功能的电脑，普通 Oink 使用仍可继续。只有本次布局依赖的参与电脑缺少能力时，才阻止应用物理布局，并提示需要升级哪台电脑。协议字段及持久化配置采用兼容扩展，空配置维持普通模式。

安装和更新遵循平台正常流程，保留原有键鼠权限、配对、音频、剪贴板及文件拖拽能力。不得为部署预览版绕过系统保护、注入认证状态或清除用户原有配置。

## 十 验收场景

### 当前桌面的实机基线

当前桌面为左侧 U27P10、右侧 GM001J，初始画面为左 Mac、右 Windows。用户已确认 GM001J 曾短暂显示 Mac 并恢复 Windows；该显示器在已测试的路径中无法读回当前输入源，应作为目视校准样例。其余能力在测试时重新确认，不把这一现场结论推广到所有同型号硬件。

### 验收矩阵

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| A01 | 首次配置两屏两电脑 | 常规流程不要求输入原始控制码，左右位置和各输入电脑关系可确认 |
| A02 | 两台电脑系统排列与物理顺序不同 | 按用户确认的物理顺序展示并移动鼠标 |
| A03 | 两块同型号或无唯一序列号的屏幕 | 不错误合并，允许逐块目视匹配 |
| A04 | 校准成功、失败和取消 | 一次仅测试一块屏，按时进入恢复，恢复后才确认保存关系 |
| A05 | 无法读回输入源 | 能完成有基线的目视校准，不声称硬件读回成功 |
| A06 | 12 完整模式 | 左 Mac 右 Windows；双方不可见目标屏从系统桌面停用，可见主屏正确 |
| A07 | 21 完整模式 | 左 Windows 右 Mac；同上，并验证鼠标双向跨屏 |
| A08 | 11 和 22 | 两屏画面归属正确；另一端无可见屏时通信和恢复有效，系统保护导致的兼容处理明确 |
| A09 | 在原主屏切走时操作 | 新可见屏可操作；确认按钮、菜单栏或任务栏可达 |
| A10 | 普通窗口、对话框、全屏、图标 | 不因保留被管理的隐藏桌面而丢失操作入口；应用特例有明确处理 |
| A11 | 已停用屏重新分配回来 | 可重新启用、识别、切源并建立正确路由，无需重新配置绑定 |
| A12 | 未确认布局 | 15 秒后开始恢复前一完整状态，界面显示恢复结果 |
| A13 | 关闭设置界面或应用主进程异常 | 恢复保护按设计执行；重启可处理未完成操作 |
| A14 | 中途掉线、命令失败或读回不一致 | 不报告完整成功；已改变部分可恢复，失败项目可定位 |
| A15 | 双端同时切换、重复点击、旧确认 | 只有一个有效操作，过期请求不影响新状态 |
| A16 | 手动切源、重接线、睡眠唤醒 | 不默认为旧状态仍准确；配置保留，可局部重新确认 |
| A17 | 某一端不能系统停用或缺少适配器 | 设置时说明，用户明确采用兼容模式，布局状态准确 |
| A18 | 旧版电脑或无关电脑离线 | 普通功能可用；只限制依赖缺失能力的物理布局 |
| A19 | 退出物理模式 | 输入、系统启停、主屏和路由恢复；硬件变化下说明安全恢复结果 |
| A20 | 现有功能回归 | 配对、键鼠、剪贴板、音频和文件拖拽不因本功能回退 |
| A21 | 非目标屏幕和用户自有内屏 | 未纳入管理的显示器不被意外停用、改模式或改位置 |
| A22 | 超过首版规模 | 给出明确范围或使用逐屏选择，不因组合上限出现空白界面 |

自动化覆盖配置和能力校验、状态转换、超时确认、失败补偿、并发、协议兼容、UI 引导和恢复入口。涉及物理输入和系统桌面的验收必须包含两端实机；模拟测试不替代画面确认。

性能目标是点击后立即出现反馈，长操作持续显示当前阶段。输入切换、系统重枚举及恢复耗时记录实测结果后设定平台超时，不用固定的理想速度掩盖硬件差异。

## 十一 实施和上游交付

按以下顺序推进，每一阶段保留可以运行和验证的结果：

1. 整理现有实现与能力边界，确定数据模型及原版兼容策略；保留已验证输入路径。
2. 完成物理位置与输入关系校准向导，替换常规用户需要操作技术表单的流程。
3. 完成可协调、可确认和可恢复的布局应用过程。
4. 实现 Windows 系统桌面管理及 Mac BetterDisplay 适配，分别验证 12、21 和无可见屏的 11、22。
5. 完成主屏、退出恢复、异常场景和原有功能回归，再形成可供用户体验的预览版。

上游可以拆分为有明确依赖的 PR：物理屏幕模型与路由、校准和布局交互、平台桌面管理与恢复。拆分只用于方便评审，不能让功能入口对未完成能力作出完整模式承诺。

PR 应说明具体用户问题、最终行为、平台能力边界、兼容模式和实机验证结果，并提供简短的向导与四布局切换演示。复用项目组件、国际化、配置、协议和已有测试体系；仓库中不包含现场用户配置、凭据、构建产物和一次性执行日志。

首版完成的判断是用户能够从零配置并安全完成日常布局操作，且验收矩阵中的失败场景有明确结果。只生成四个按钮、只切换输入源、只隐藏 Oink 路由中的屏幕或仅生成安装包，均不足以完成该目标。
